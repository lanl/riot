# Proposed changes: CT ideal MHD in the hydro package (PR #54)

This file was generated with agentic AI (Claude Code). The first part is the plan
approved before implementation started, reproduced as written. The last section
records where the merged code departs from that plan, as a result of review and testing.

## Original plan: CT ideal MHD in Riot (inside the hydro package)

### Context
Riot has no MHD. We want ideal MHD as an option of the existing hydro package (`<hydro>/mhd = true`):
- HLLD (ported from the untracked `athena_hlld.cpp`, Athena++/Miyoshi–Kusano) is added to the Riemann solvers and forced when MHD is on.
- Face-centered B is evolved with constrained transport, following `external/parthenon/example/fine_advection`: a Face field with `WithFluxes` gets an automatic Edge flux (the EMF), the update is a Stokes curl, and Parthenon already provides edge flux correction and Toth–Roe div-free prolongation for AMR.

Decisions so far:
- Gardiner–Stone 2005 upwind corner EMFs (Athena++ `wct` weighting).
- Heaviside–Lorentz units (p_B = B²/2).
- Cartesian only for the first pass.
- Error out if MHD is combined with strength or ionization.
- Deliverables include Brio–Wu, Orszag–Tang and field-loop test problems, set up through the python `region_pgen` interface (no new C++ pgens), with regression tests, plus HLLD unit tests.
- The flux kernel is not templated on MHD. B quantities are always in the pack and guarded at runtime.

### Key constraints (verified)
- **Face B memory layout.** Face B with `FillGhost` cannot be `CellMemAligned` (`external/parthenon/src/interface/metadata.cpp:296`). So `bfield` and its edge flux use node layout, and Riot's flat `make_pack_view` / `make_flux_pack_view` must never touch them. Use explicit `(b, TE, var, k, j, i)` indexing only.
- **Flag-only packs.** These would silently grab face B: `sparse_update::UpdateToNextStage` (`src/riot_utils/sparse_update.hpp:154`), `DeepCopyData` / `DeepCopyIndependentData` (:235, :265), and the radiation `DeepCopyData` calls. Each needs `Metadata::Cell` added to its flags.
- **EMF sign.** Stokes (fine_advection `stokes.hpp`) adds +curl of the stored flux. Faraday gives dB/dt = −curl E, so the edge flux stores **−E**.

### Steps

#### 1. Variables (`src/variables.hpp`, `Hydro::Initialize` in `src/hydro/hydro.cpp`)
- Add a `VARIABLE_FACE_VECTOR(ns, name, sparse, ncomp)` macro, using `base_w_tt_t<false, TT::Face, ncomp>`.
- Register these only when `do_mhd`, which is stored as a hydro param:

| Field | Metadata / purpose |
|---|---|
| `bfield` (face) | `{Face, Independent, WithFluxes, FillGhost, Vector}` + `RegisterRefinementOps<ProlongateSharedMinMod, RestrictAverage, ProlongateInternalTothAndRoe>()` |
| `ccbulk::bcc` (3) | `{Cell, Derived, OneCopy}`. Cell B averaged from faces over the entire domain; output it. |
| `face_emf` (face, 2 comp) | `{Face, Derived, OneCopy, CellMemAligned}`, like `face_signal` (hydro.cpp:190). |
| `face_vrho` (face) | Same metadata. Mass-flux proxy for the upwind weight. |
| `bface_aligned` (face) | Same metadata. Cell-layout copy of the normal B for the flux kernel. |
| `ccbulk::divb` | `{Cell, Derived, OneCopy}`. Diagnostic. |

- **`face_emf` holds the transverse EMFs from the Riemann solves.** Each face stores the two EMF components HLLD returns (Athena's `ey = −F(By)` and `ez = +F(Bz)`). It is a separate Derived scratch field rather than `bfield`'s own Edge flux, for three reasons:
  - the Riemann solve lives on faces, while the edge flux lives on edges;
  - the GS05 corner kernel needs the face values from all four faces around each edge;
  - being `CellMemAligned`, it can be written with the existing flat `pv(te, var, kji)` views in the flux kernel.
- `face_emf` slot convention, with cyclic `tac=(nc+1)%3` and `tbc=(nc+2)%3` from `DirBasis` (`src/riot_utils/riot_loops.hpp:70-93`): slot0 = −F(B_tac) = E_tbc and slot1 = +F(B_tbc) = E_tac.

| Face | slot0 | slot1 |
|---|---|---|
| F1 | E3 | E2 |
| F2 | E1 | E3 |
| F3 | E2 | E1 |

- Verify that the `Vector` flag gives the correct reflecting-BC sign flip for a Face field.

#### 2. HLLD (`src/hydro/riemann.hpp`)
- Add `hlld` to `enum RiemannSolver` and `"hlld"` to the parse list (hydro.cpp:109-133).
- `template<int DIR> lr_to_flux_hlld(...)` follows the scalar-argument style of `lr_to_flux_hllc`.
  - Extra inputs: `bn`, `b{1,2,3}{l,r}`.
  - Extra outputs: `emf0`, `emf1`, `vrho`.
  - Rotate with `DirBasis<DIR>` internally.
- General EOS:
  - a² = bmod/ρ (`BulkSoundSpeed`).
  - E = u + ½ρv² + ½B², where u is the reconstructed internal energy density.
  - Fast speed: cf² = ½[(a² + B²/ρ) + √((a² + B²/ρ)² − 4a²bn²/ρ)], with the discriminant clamped at 0.
  - Star states need no EOS call.
- Port eqns 38–63 one-to-one with the `SMALL_NUMBER` degenerate guards, plus sign-preserving floors on `spd0−S_M` and `spd4−S_M`.
- Outputs:
  - `riemann_vel = F_d / (S_M ≥ 0 ? ρL : ρR)`, with face velocity = S_M. The per-material upwind sign (calculate_fluxes.cpp:697-707) must match, so Σ material mass fluxes = F_d.
  - `v{1,2,3}face` = velocity of the selected fan state.
  - `vrho = 2F_d / (ρL + ρR)`.
  - Return max(|spd0|, |spd4|).

#### 3. Flux kernel (`src/hydro/calculate_fluxes.cpp`)
- **No `MHD` template.** This follows the strength precedent: `shear_modulus` and `face_velocity` are always in the pack but only registered with strength/ionization, and are guarded at runtime (calculate_fluxes.cpp:100-109, 700-704).
  - Add `bcc, bface_aligned, face_emf, face_vrho` to the single existing `riot::MakePack` list.
  - Absent vars get size 0 / nullptr view slots, so they are safe as long as no access happens. Every access is guarded by `do_mhd` (or `rsolver == hlld`), outside inner loops.
- **Scratch for reconstructed `bcc`** (3 comp × 2 halo × 2 = 12 Reals per point, against roughly 580 already, of which roughly 344 are strength-only):
  - Call `AddTypeIndexedPerPointScratch<…, bcc_recon_types>` only `if (do_mhd)`. That makes it free on team-scratch backends.
  - Call `GetTypeIndexedPerPointScratch` only inside the MHD branch. On the default GPU `boiv` tag and on the host raw backend, storage is created at `Get*`.
  - The residual cost for non-MHD runs is register pressure from the inlined HLLD path, the same trade-off strength already makes. If profiling shows a regression in non-MHD runs, fall back to templating `CalculateFluxesImpl<DIR, bool MHD>`.
- Pre-pass `CopyFaceBToAligned` over entire face bounds, with direct indexing.
- Reconstruct `bcc` with the existing `ReconCells<pressure, bulk_modulus, velocity, bcc>` and add matching per-point scratch. The normal component comes from `bface_aligned`.
- nhalo ≥ 1 when MHD, since the corner stencil needs transverse ghost-row face EMFs. Add +1 to the stencil-width / nghost check in hydro.cpp.
- Add a `case hlld:` that writes momentum, energy, face_signal and face velocity as in HLLC, plus `face_emf(0/1)` and `face_vrho`.
- Force `hlld` when `do_mhd`, as `strong` is forced at :737.

#### 4. Corner EMF (new `src/hydro/ct.cpp`, declared in `hydro.hpp`)
- `Hydro::CalculateCornerEMF(md, dt)`:
  - **(A)** No stored cell EMF. The GS05 reference E_n,cc = −(v×B)_n in each of the 4 cells around an edge is computed inline from `velocity` and `bcc`. It is two products per cell.
  - **(B)** GS05 / Athena `calculate_corner_e` for each edge, with weight `w = 0.5 + clamp(512·dt·vrho/dx, ±0.5)`, permuted cyclically for E1 and E2.
- Edges by dimension:
  - 2D: full GS05 for E3; E1 = F2 slot0 and E2 = F1 slot1, taken directly (needed for Bz).
  - 1D: E3 = F1 slot0, E2 = F1 slot1, E1 = 0.
- Write `flux(b, TE::En, bfield(), k, j, i) = −E_n`.
- Also add `FaceToCellB(md, domain)` and `CalculateDivB(md)` here.

#### 5. Update and driver (`src/riot_utils/sparse_update.hpp`, new `src/riot_utils/stokes.hpp`, `src/riot_driver.cpp`)
- Copy `external/parthenon/example/fine_advection/stokes.hpp` into `src/riot_utils/stokes.hpp` under a Riot namespace.
- Add `UpdateFaceFieldsToNextStage(mu0, mu1, gam0, gam1, beta_dt)`: for F1–F3 over interior bounds, `u = gam0·u + gam1·u0 + beta_dt·Stokes`. It matches the low-storage weights.
- Add `Metadata::Cell` to the flags of `UpdateToNextStage`, `DeepCopyIndependentData` and the radiation `DeepCopyData` calls. Add `DeepCopyFaceData` and call it next to riot_driver.cpp:191.
- Task order in `RiotStepTasks`:
  1. CalculateFluxes
  2. CalculateCornerEMF
  3. LoadAndSendFluxCorrections, which moves edge fluxes automatically via `WithFluxes`
  4. SetFluxCorrections
  5. UpdateToNextStage ∥ UpdateFaceFieldsToNextStage
  6. FillInteriorDerived
  7. boundary exchange, which includes Toth–Roe internal prolongation
  8. PostCommsFillDerived
- Verify that Riot's flux-correction path doesn't filter edge fluxes out.

#### 6. Derived quantities, energy and timestep
- `src/multiphysics/fill_shared_derived.cpp`:
  - `FillInteriorDerived`: call `FaceToCellB(interior)` first, then `u = E − ½ρv² − ½|bcc|²` (~line 99), with a floor.
  - `PostCommsFillDerived`: call `FaceToCellB(entire)`, then `E = u + ½ρv² + ½|bcc|²` (~333), then `CalculateDivB`.
- Timestep in `EstimateTimestepMesh` (hydro.cpp:717-726): use the directional fast speed cf_d computed from bcc.
- Grep other E↔u conversions (`diagnostics/energies.cpp`, pgens, mix) and add the magnetic term, or block the combination.
- History outputs: max normalized |div B| and total magnetic energy (pattern in `src/diagnostics/energies.cpp:96-106`).

#### 7. Validation (`Hydro::Initialize`, `src/riot.cpp` ~103-120)
- MHD forces hlld, with a warning if the user explicitly set another solver.
- `riemann=hlld` without MHD is an error.
- Require UniformCartesian coordinates.
- Error if MHD is combined with strength, ionization, radiation transport, BHR mix or sparse_physics. The last three can be relaxed later.

#### 8. Initial conditions through the python region pgen, plus tests
No new C++ pgens. Instead, extend `region_pgen` (`src/riot_pgen/regions.{hpp,cpp}`, `region_python.hpp`) so a python class can set B.
- **New optional methods on the default `<regions>` class.** Using only the global class keeps A and B continuous across region boundaries, so ∇·B = 0 holds there.
  - `f_b_vector_potential(self, pos, out)`: sampled at edge centers, `out` shape (n,3). Preferred, because it is discretely div-free.
    - For each E1/E2/E3 over the block including ghosts, build edge-center `sample_positions_t` and make one batched call per edge type. Take component d for E_d.
    - Face B is the discrete curl (fine_advection `parthenon_app_inputs.cpp:148-177` style, using `coords.Volume(TE)` edge lengths and face areas).
  - `f_b_bfield(self, pos, out)`: B sampled directly at face centers, taking the normal component per face TE. Meant for 1D problems and uniform normal fields such as Brio–Wu, where it is trivially div-free.
  - If both are provided, that is an error.
- **Where it plugs in.** Add a post-pass in `BlockInitData::InitBlock` (`regions.cpp`), after `set_clean_state` / `set_dirty_state` (~352-356) and before `FillInteriorBlockDerived` (~366).
  - Fill the face-B host mirror and copy it to device.
  - Average to `bcc` and add ½|bcc|² to `total_material_energy`.
  - Keep B out of the generic `bulk_state` / dirty-cell loops: they only write component 0 (regions.hpp:1157-1161).
- **Input scripts** in `inputs/mhd/`, each `region_pgen` + python classes in the style of `inputs/advection/advection_smooth.py` and `inputs/kh.py`:
  - `brio_wu.py`: background + `inside_rectangle` constant states, and `f_b_bfield`.
  - `orszag_tang.py`: background python class, and `f_b_vector_potential` with A_z = B0[cos4πx/(4π) + cos2πy/(2π)], B0 = 1/√(4π).
  - `field_loop.py`: A_z = A0·max(R − r, 0), uniform v, periodic, AMR.
- The test harness already runs `inputs/<x>.py` (`tst/scripts/utils/riot.py:83-91`).
- Regression tests: `tst/scripts/mhd/`.
  - Brio–Wu: gold comparison.
  - Orszag–Tang t=0.5: gold comparison.
  - Field loop with AMR: |div B| ≲ 1e-12 at all times, plus a bound on magnetic-energy decay.
- Unit tests in `tst/unit/test_riemann.cpp` (X1/X2/X3):
  - B=0 HLLD == HLLC.
  - Identical L/R states give the exact MHD flux, with emf0/emf1 = (−v×B) components.
  - Stationary contact gives zero mass flux.
  - Tangential discontinuity.
  - bn→0 stays finite.
  - Mirror symmetry.
  - Signal speed ≥ |v| + cf.

### Verification
1. Build, then run `tst/unit` (Catch2): all HLLD tests pass.
2. Brio–Wu in X1, then rotated to X2 and X3 (exercises the cyclic permutations and the EMF sign), compared with the reference.
3. Field-loop advection in 2D, uniform and then AMR (3 levels): div B at round-off from the history output, and the loop advects in the correct direction (checks the EMF sign).
4. Orszag–Tang in 2D: the structure matches published / Athena++ results, and the run is stable to t=1.
5. Existing hydro regression suite: unchanged results with MHD off.

## Changes relative to the plan

- **Geometry.** CT and the MHD source terms take edge lengths and face areas from the
  coordinates, so uniform cylindrical (RZ) coordinates are supported alongside Cartesian
  (`field_loop_rz` test). Other coordinate systems are rejected at initialization.
- **Field names.** The face scratch fields are `ffbulk::bnormal`, `ffbulk::vrho` and
  `ffbulk::emf`. Cell B is `ccbulk::bfield` and the face B is `ffbulk::bfield`.
- **Validation.** The code rejects MHD combined with strength, ionization, radiation
  transport or the BHR mix model. It disables sparse_physics rather than erroring.
- **No copied `stokes.hpp`.** The face update lives in `src/hydro/ct.cpp`.
- **DeepCopy.** The plan proposed adding `Metadata::Cell` to the flag-only packs and
  a separate `DeepCopyFaceData`. Instead, `DeepCopyData` is generic over topological type
  and memory layout. Cell-aligned and node-layout variables are split into separate
  packs, one kernel launch each. `DeepCopyIndependentData` copies the cell and face
  independent fields.
- **nvcc compatibility.**
  - The DeepCopy kernel is compiled in a single translation unit
    (`src/riot_utils/sparse_update.cpp`). A header-template extended lambda
    instantiated in several TUs was merged at link time with another TU's unset nvcc
    lambda helpers, which crashed on V100.
  - Variables first captured inside `if constexpr` branches of extended lambdas were
    moved into device helpers.
- **Additions from review.**
  - A runtime PLM slope limit, `hydro/plm_slope_limit`.
  - AMR, block-size and output-interval options for the Orszag–Tang deck.
  - More tests: `field_loop_3d`, `field_loop_aniso` and `rotating_pinch`.
  - Documentation in `doc/sphinx/src/packages/mhd.rst`.
